Here is the full DNS resolution workflow in ASCII text format:

```
 User
   |
   |--[google.com?]--> Resolver Server
   |                          |
   |                          |--[google.com?]--> Root Server
   |                          |                          |
   |                          |                          |--[TLD Server?]--> Top Level Domain (TLD) Server
   |                          |                          |                          |
   |                          |                          |                          |--[NS Record]--> NS54.WORLDNIC.COM
   |                          |                          |                          
   |                          |                          |<--[173.194.10.4]--------|
   |                          |
   |                          |--[google.com?]--> Authoritative Name Server
   |                          |                          |
   |                          |                          |--[IP Address?]--> 74.120.44.55
   |                          |
   |<--[74.120.44.55]--------|
```

### Explanation:
1. The user requests `google.com` via their browser.
2. The request goes to the **Resolver Server** (local DNS resolver).
3. The resolver queries the **Root Server**, which points it to the **TLD Server** for `.com`.
4. The **TLD Server** provides the Name Server (`NS54.WORLDNIC.COM`).
5. The resolver then queries the **Authoritative Name Server**, which returns the IP address (`74.120.44.55`).
6. The resolver caches the response and returns it to the user.
7. The user’s browser connects to `74.120.44.55`, loading `google.com`.

This is a simplified representation of how DNS resolution works! 🚀
