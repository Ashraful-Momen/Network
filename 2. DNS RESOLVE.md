Sure! Here's the full DNS resolution journey in ASCII format, including `NS1`, `NS2`, and other key steps:  

```
 User's Computer
     |
     |--[google.com?]--> Local Resolver (ISP's DNS)
     |                        |
     |                        |--[google.com?]--> Root DNS Server
     |                        |                       |
     |                        |                       |--[google.com?]--> TLD Server (.com)
     |                        |                       |                       |
     |                        |                       |                       |--[NS Record]--> NS1.google.com, NS2.google.com
     |                        |                       |
     |                        |                       |<--[Referral: NS1, NS2]--|
     |                        |
     |--[google.com?]--> NS1.google.com (Authoritative Name Server)
     |                        |
     |                        |--[Checks for google.com]  
     |                        |                          |
     |                        |                          |--[Finds A Record]--> 142.250.190.46
     |                        |
     |<--[142.250.190.46]-----|
     |
 Browser connects to 142.250.190.46 and loads google.com
```

### **Step-by-Step Breakdown:**
1. **User's Computer Requests google.com**  
   - The request first goes to the **Local Resolver** (ISP's DNS Server).  
2. **Local Resolver Queries the Root Server**  
   - The **Root DNS Server** doesn’t have the IP but knows which **TLD Server (.com)** to ask.  
3. **TLD Server Queries**  
   - The **TLD Server** checks for `google.com` and returns a list of **Google’s Name Servers** (`NS1.google.com, NS2.google.com`).  
4. **Querying Authoritative Name Server (NS1.google.com)**  
   - The resolver then asks **NS1.google.com** for the IP address of `google.com`.  
   - The authoritative name server finds the **A record** (`142.250.190.46`).  
5. **Local Resolver Caches and Returns the IP**  
   - The resolved IP (`142.250.190.46`) is returned to the user's browser.  
6. **User’s Browser Connects to the IP**  
   - The browser establishes a connection to `142.250.190.46` and loads `google.com`.  

### **Additional Details:**
- `NS1.google.com, NS2.google.com`: These are **Authoritative Name Servers** responsible for `google.com`.
- **Caching**: The resolver caches the IP for faster future lookups.
- **Recursive Queries**: The resolver performs all the queries on behalf of the user.
